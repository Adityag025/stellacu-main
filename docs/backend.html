Website backend

How the StellAcu Media website handles its forms: what runs where, how to set it up, and how to change it.

Overview Setup Folder structure API endpoints Front end Local development Tests Common changes Shared hosting Security

Overview

The site is static HTML hosted on Vercel. The only server-side code is a set of Vercel serverless functions in the api/ folder. Vercel deploys them automatically with every push to main; there is no separate server to run or maintain.

1. BrowserVisitor submits a form. js/app.js sends JSON to /api/…
2. API functionChecks the method, honeypot and every field against api/_lib/forms.js
3. ProviderEmails the team through Resend, or adds the subscriber to Mailchimp
4. BrowserShows the thank-you message, or an error if something failed

There is no database. Enquiries arrive as emails in the team inbox, with the visitor set as reply-to so you can answer directly.

Setup (one time)

Required  Until these settings exist, the forms answer not_configured and visitors see an error message.

1. Email sending (Resend)

  1. Create an account at resend.com.
  2. Domains → Add domain → stellacumedia.com, then add the DNS records it shows at your domain registrar. Wait until the domain shows Verified.
  3. API Keys → Create API key (permission: Sending access). Copy it.

2. Environment variables on Vercel

Vercel → the project → Settings → Environment Variables. Add each one for the Production environment (and Preview if you want preview deploys to send email):

NameExampleNeeded for
RESEND_API_KEYre_…All forms
MAIL_FROMStellAcu Website <website@stellacumedia.com>All forms (domain must be verified in Resend)
MAIL_TOsales@stellacumedia.comAll forms (comma-separate several inboxes)
MAILCHIMP_API_KEYabc123…-us10Optional: newsletter into Mailchimp
MAILCHIMP_AUDIENCE_IDa1b2c3d4e5Optional: newsletter into Mailchimp
MAILCHIMP_DOUBLE_OPT_INtrueOptional (default true: subscribers confirm by email first)

Then Deployments → … → Redeploy the latest deployment so the functions pick up the new values.

3. Check it

Open https://<your-domain>/api/health. You should see:

{ "ok": true, "email": true, "newsletter": "email" }   // or "mailchimp"

Then send a test enquiry from the Start a Growth Audit page and confirm it arrives.

The backend has no npm dependencies: it uses Node's built-in fetch, crypto and test runner. The only package, puppeteer-core, is a dev dependency used by the browser tests.

API endpoints

All endpoints take and return JSON. Every response has ok; failures add an error code and, for validation errors, a fields object with one message per field.

POST /api/contact

{
  "form": "growth-audit",          // "growth-audit" | "landing-1" | "landing-2"
  "fields": {
    "name": "Asha Rao",
    "email": "asha@example.com",
    "phone": "+91 98765 43210",
    "company": "Acme",
    "message": "…"
  },
  "page": "/start-a-growth-audit.html",
  "botcheck": ""                   // honeypot, must be empty
}

Which fields are accepted and required depends on form, see api/_lib/forms.js.

POST /api/subscribe

{ "email": "reader@example.com", "page": "/index.html", "botcheck": "" }

GET /api/health

{ "ok": true, "email": true, "newsletter": "mailchimp" | "email" | "none" }

Only reports true/false; never shows setting values.

Front end

The Website Forms section of js/app.js handles all four forms:

  • #contact-form and #audit-form: collects every named input, sends { form: data-form, fields, page, botcheck } to /api/contact.
  • .notify-form (footer): sends the email to /api/subscribe.
  • On success the form's .form__reply message shows for 5 seconds, then the form resets. On failure the contact forms show an alert and the footer shows its error message.

Field validation in the browser

Before anything is sent, every field is checked with the same rules and messages as api/_lib/validation.js. Every field on every form is required. Which rule a field uses comes from its name (FIELD_TYPE_BY_NAME in js/app.js, the type in api/_lib/forms.js):

FieldRuleMessage
any, when emptyrequiredThis field is required. / Please choose an option.
nameletters in any language, spaces, apostrophes, hyphens, dots; 2–100 charactersUse letters only (spaces, apostrophes and hyphens are fine).
emailname@domain.tld with a letter TLD of 2+ characters, no "..", max 254Enter a valid email address.
phone7–15 digits; spaces, ( ) . - allowed, + only at the startEnter a valid phone number (7 to 15 digits).
company2–200 characters, anything allowed (3M, AT&T)Please enter at least 2 characters.
message10–5000 charactersPlease enter at least 10 characters.
websitepublic domain like acme.com (https:// optional); no IPs, no localhost, max 500Enter a valid website address, e.g. example.com.
budgetone of the listed optionsPlease choose an option.
too longover the field's maximumPlease use N characters or fewer.
  • Messages appear under the field (.field-error) and the field gets a red border (.is-invalid, styles at the end of css/custom.css).
  • A field is checked when the visitor leaves it, and re-checked as they type until it is fixed. On submit every field is checked and the first problem gets focus.
  • If the server still rejects a field (422), its message appears under that field the same way.
  • The browser's own pop-up messages are turned off (novalidate) so only these show.

If you change a rule, change it in both js/app.js and api/_lib/validation.js; the server is the one that counts.

In the HTML, the input name attributes must match the field names in api/_lib/forms.js (all lower case), and each contact form needs a data-form attribute.

Local development

Requires Node.js 22 or newer.

cp .env.example .env.local     # optional: fill in real keys to send real emails
npm run serve                  # http://localhost:3000

This serves the site and the API exactly as Vercel does. Without .env.local the forms answer not_configured, which is fine for layout work. Use a different port with PORT=4000 npm run serve.

Alternatively, with the Vercel CLI: vercel dev (uses the environment variables from your Vercel project).

Pages use clean URLs (/about-us, not /about-us.html). In links, write href="about-us" (or ../about-us from insights/) and href="/" for home. VS Code Live Server does not support clean URLs; use npm run serve.

Opening the HTML files directly from disk (file://) does not work: the header/footer includes and the API both need a web server.

Tests

npm test

Runs everything in tests/ with Node's built-in test runner. The tests call the handlers directly with fake requests and fake email/Mailchimp clients, so they need no network and no keys. They cover validation rules, email content and escaping, every status code, the honeypot, the Mailchimp/email fallback, and the exact requests sent to Resend and Mailchimp.

Run them before every push that touches api/.

Browser tests (whole site)

npm install            # once: installs puppeteer-core (uses your installed Chrome)
npm run serve          # terminal 1
npm run test:site      # terminal 2
BASE_URL=https://stellacu-main.vercel.app npm run test:site   # check production instead

These open the real pages in Chrome (tests/site/*.site.js) and check:

FileChecks
pages.site.jsCrawls from the home page: every page loads (200), has its header and footer, no broken internal links or assets, no .html in links; old .html addresses 308-redirect; unknown URLs get the 404 page.
fonts.site.jsAll visible text is Poppins and every weight used is loaded, at desktop (1440px) and phone (390px) widths.
spacing.site.jsEvery section follows the shared spacing rule, and no gap between sections is oversized, at both widths.
forms.site.jsAll four forms: empty submit flags every field, each field's rule and message, valid data is sent, server field errors show under the field. API calls are intercepted, so no email is sent.

Set CHROME_PATH if Chrome is installed somewhere unusual. Run them before pushing layout or form changes.

Section spacing

All gaps between page sections come from one rule at the end of css/custom.css ("Section spacing"): each section after the first has no top padding and --section-gap of bottom padding (90px phone, 110px tablet, 130px laptop, 150px large screens). Sections with a background or divider lines get the class section-band and use half the gap on each side of the line. The full-screen home hero (section-hero) and the "Let's talk" section before the footer keep their own spacing. Do not add padding or margin to sections inline; change --section-gap instead.

Common changes

Add a field to an existing form

  1. Add it to the form in api/_lib/forms.js, e.g. role: { label: 'Role', type: 'text' }. Types: name, text, longText, email, phone, url, choice (with options).
  2. In js/app.js, add the field name to FIELD_TYPE_BY_NAME with the same type.
  3. Add the input to the HTML with name="role".
  4. Add or update a test, run npm test.

A field in the HTML that is not in forms.js is silently ignored, so step 1 is required.

Add a new form

  1. Add a new key in api/_lib/forms.js with its subject and fields.
  2. In the HTML: <form id="contact-form" data-form="your-key">, a hidden botcheck checkbox (copy it from an existing form), the inputs, and a sibling .form__reply element with the thank-you text.
  3. If the form needs a different id, add it to the selector in the Website Forms section of js/app.js.

Change where enquiries go

Change MAIL_TO on Vercel and redeploy. No code change.

Switch email provider

Write api/_lib/providers/<name>.js exporting sendEmail() with the same arguments as resend.js, then change the require in api/contact.js and api/subscribe.js. Nothing else depends on Resend.

See errors in production

Vercel → the project → Logs (filter by /api/). Handlers log [contact] / [subscribe] lines with the reason for every 502 and 503.

Hosting on shared hosting (Hostinger)

The live site stellacumedia.com runs on Hostinger shared hosting. It serves the pages and runs the PHP form API in php-api/ (shared hosting runs PHP, not Node.js). The PHP API answers the same addresses as the Node.js one on Vercel (/api/contact, /api/subscribe, /api/health), with the same JSON responses and validation messages, and sends email through the Hostinger mailbox sales@stellacumedia.com. The Vercel deployment stays as a preview with its Node.js API.

FileRole
php-api/contact.php, subscribe.php, health.phpThe three endpoints (mirror api/*.js)
php-api/_validation.php, _forms.phpSame rules/messages and form definitions as api/_lib/validation.js / forms.js; keep them in sync
php-api/_email.phpNotification email + SMTP over SSL to smtp.hostinger.com:465; optional Mailchimp
php-api/_ratelimit.phpSpam protection: 5 submissions per visitor per 10 minutes (429 too_many_requests)
php-api/config.local.phpMailbox password and settings. Only on the server: git-ignored, not in the upload bundle. Create it from config.example.php
  1. Build the upload: npm run build:upload copies exactly the needed files to dist/upload/ (17 pages, insights/, partials/, css/, js/, fonts/, img/, video/, php-api/, .htaccess).
  2. Upload to public_html (hPanel File Manager, or FTPS). index.html and .htaccess must be directly in public_html.
  3. Once: upload php-api/config.local.php with the mailbox password.
  4. Check: https://stellacumedia.com/api/health shows "email": true, "backend": "php", and node --test tests/site/api-parity.site.js confirms the PHP and Node APIs answer identically. (Hostinger's bot check blocks headless Chrome, so run the page tests against a local copy or Vercel.)

.htaccess routes /api/… to php-api/, blocks direct access to php-api/, and does what vercel.json does on Vercel: clean URLs (/about-us serves about-us.html, including /partials/header), 301 redirects from old .html addresses, HTTPS, the 404 page, compression, caching, and refusing backups, hidden files and developer folders.

Security notes

  • Secrets never go in the code or the browser: on Vercel in environment variables, on Hostinger in php-api/config.local.php (blocked from the web). .env.local and config.local.php are git-ignored.
  • The email subject and the list of accepted fields are fixed on the server; visitors cannot change them.
  • Every field is length-limited and type-checked; visitor text is HTML-escaped in the email.
  • Spam protection: a honeypot checkbox, plus (PHP API) 5 submissions per visitor per 10 minutes. On Vercel, add a rate-limit rule in Vercel → Firewall for /api/*.
  • Request bodies over 20 KB are rejected.
